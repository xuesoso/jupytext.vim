# jupytext.vim Release Notes

## Unreleased

* Conversion daemon (Neovim): conversions can run through a persistent helper
  process that imports `jupytext` once, turning the ~0.2s Python/import startup
  paid on *every* open and save into a one-time cost. Opening and saving drop
  to a few milliseconds (`let g:jupytext_daemon = 1`, default on). Falls back
  transparently to the `jupytext` CLI when no usable Python is available, so
  correctness never depends on it. Configure the interpreter with
  `g:jupytext_python` (auto-detected from the `jupytext` shebang by default).
  The daemon currently requires Neovim; classic Vim uses the CLI path.
* Respect notebook format metadata: a notebook paired/configured for a specific
  text format (e.g. `py:percent`) now opens in that format instead of always
  using `g:jupytext_fmt` (`let g:jupytext_respect_metadata = 1`, default on,
  requires the daemon).
* Safer failures: if a notebook cannot be converted on open (jupytext missing,
  invalid notebook, bad `g:jupytext_fmt`) the plugin now shows the raw notebook
  JSON read-only with a clear message, instead of leaving an empty, writable
  buffer whose `:w` would overwrite the `.ipynb` with nothing. A preflight
  check reports a missing `jupytext` up front.
* Non-blocking saves: the ipynb is now regenerated by a detached background job
  instead of freezing the editor on every `:w` (`let g:jupytext_async = 1`,
  enabled by default). Rapid saves are collapsed into a single re-run, failures
  are reported via `:messages`, and the conversion is allowed to outlive `:wq`
  so the notebook is never left stale. Falls back to the original blocking
  behavior when set to `0` or on Vim builds without job support. This is the
  path used in classic Vim and whenever the daemon is unavailable.
